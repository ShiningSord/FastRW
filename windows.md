# Experimental Windows / NVIDIA CUDA setup and launch guide

[中文版](windows.zh.md)

**The Windows version has not been rigorously tested by the project maintainers
and is provided for reference only.** Numerical accuracy, stability, performance,
and compatibility across Windows/CUDA environments remain unverified. A successful
launch does not establish equivalence with the Metal backend or reproduce the
paper's accuracy and speedup results.

This backend is adapted from the community contribution by
[Cai-Shengnan in PR #11](https://github.com/ShiningSord/FastRW/pull/11).

## Requirements

- 64-bit Windows with an NVIDIA GPU and its driver.
- A CUDA Toolkit supporting your GPU and installed MSVC compiler.
- Visual Studio C++ Build Tools with the **Desktop development with C++** workload
  and a Windows SDK.
- PowerShell and Conda.

The Conda environment supplies Python, CMake, and optional Node.js/plotting tools;
install the NVIDIA driver, CUDA Toolkit, and Visual Studio Build Tools separately.
The launcher imports the MSVC environment and uses CMake with NMake. Compiler
compatibility checks are retained: if CUDA rejects the installed MSVC version,
use a compatible toolchain rather than assuming the build is supported.

## Environment and input data

From PowerShell in the repository root:

```powershell
conda env create -f .\environment-windows.yml
conda activate FastRW
.\scripts\fetch_artifacts.ps1
```

The extraction script expands the bundled `resrw-artifacts-v1.zip`, including
reference `data/` and precomputed `outputs/`, and replaces matching files.
Skip extraction if the required input data is already present. The bundled
outputs are reference artifacts, not results generated by the CUDA backend.

## Small launch test

```powershell
.\scripts\build_and_run_cuda.ps1 `
    -Config .\configs\tcad_table1\fastrw_case1.json `
    -NumSamples 2 `
    -ThreadsPerBlock 256 `
    -CudaArchitecture 86
```

`CudaArchitecture` is the CUDA compute capability without a decimal point; the
default `86` is intended for a compatible GPU, such as the contributor's RTX
3050 Ti. Set it to a value supported by both your GPU and CUDA Toolkit. This is
not a claim that other GPU/toolchain combinations have been tested.

The script explicitly enables the otherwise disabled `FASTRW_ENABLE_CUDA` CMake
option and builds `build-cuda\random_walker_cuda.exe`. CUDA builds require CMake
3.18 or newer; the supplied Conda environment requests 3.24 or newer.

A completed run prints the device name and `CUDA simulation complete`. Two
samples per query point only exercise startup and output generation; they do not
validate statistical accuracy.

For this configuration, output is written to:

```text
outputs\tcad_table1\fastrw_case1\cuda-experimental\
    direct.csv
    constraints.json
    last_random_walker_cuda.log
    summary.json
```

`diagnostics.json` is also written when diagnostics are enabled in the config.
The summary is written by the PowerShell launcher. Repeating the same case
replaces its experimental output files. The standard reproduction report does
not consume these experimental outputs.

## Additional runs

```powershell
# One FastRW or PIRW case; these are sampling settings, not validated results.
.\scripts\run_fastrw_direct.ps1 -Case 1 -NumSamples 8192 -CudaArchitecture 86
.\scripts\run_pirw_direct.ps1 -Case 1 -NumSamples 4096 -CudaArchitecture 86

# Run all three cases with the selected settings.
.\scripts\run_fastrw_direct.ps1 -Case all -CudaArchitecture 86
.\scripts\run_pirw_direct.ps1 -Case all -CudaArchitecture 86
```

`-ThreadsPerBlock -1` selects 256 threads per block. All direct-run wrappers
accept `-CudaArchitecture`, `-NumSamples`, and `-ThreadsPerBlock`.

To run an already built executable from the repository root:

```powershell
.\build-cuda\random_walker_cuda.exe .\configs\tcad_table1\fastrw_case1.json 2 256
```

The arguments are configuration path, samples per point, and threads per block.
The executable also appends `cuda-experimental` to the configured output directory,
so direct invocation uses the same isolated output location.

## Kernel maintenance

The CUDA source is generated from the reference Metal kernel and a CUDA host
adapter. After updating `src/walker_metal.mm`, regenerate it with:

```powershell
python .\scripts\generate_cuda_port.py
```

Edit the generator for CUDA host-adapter changes. Regeneration alone does not
validate CUDA behavior; changes still require Windows/NVIDIA testing.
